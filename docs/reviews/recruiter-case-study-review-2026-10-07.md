## Overall hiring read

The portfolio makes a credible case for a product designer who works through implementation, with substantial enterprise CMS experience. WheelRack's ownership statement separates the design system and product work from Cheryl's React build. The AEM study names Ryan's production Sass. PlayDraft names the agent-assisted build and release. Keep those distinctions: they make the breadth believable.

For design-engineering hiring, the strongest evidence is component behavior, production Sass, responsive implementation, plugin behavior, and motion across runtimes. Screen counts, token counts, and test counts establish scope but do not prove code quality or product judgment by themselves. Show one actual implementation decision with its resulting behavior in each technically focused study.

For product-design hiring, the portfolio has strong constraints and decisions. Its weaker area is validation outside Ryan's own judgment. Where research or testing happened, show one actual observation and the decision it changed. Where it did not happen, retain the honest status and describe the current learning question. Do not add a generic research process retrospectively.

For AEM hiring, the combination is unusually complete: component variants, production styles, templates, permissions, DAM cleanup, SEO, accessibility, authoring training, experience fragments, and Target coordination. Three studies should explain three separate responsibilities: build the foundation, enable page authors, and orchestrate audience experiences.

## Fix these before expanding the portfolio

1. **Separate the overlapping stories.** Governance owns the four-plugin starter-to-handoff system. Tools that scale design owns the crop simulator and other adopted utilities. AEM Components owns the implementation contract, Landing Pages owns authoring and review, and Seasonal Content owns audience mapping and swaps.
2. **Tighten metric evidence.** Highest priority: AEM's 60% speed claim, Tire Categories' conversion/search lifts, and landing-page turnaround by complexity. Preserve cohort and attribution limits beside the number. Avoid universal claims such as “15 years of DAM debt resolved” unless the full scope was actually completed.
3. **Resolve copy-to-artifact mismatches.** LoopStack's older captions and screens, PlayDraft's deep feature inventory versus its simplified loop, and landing-page annotations versus its qualified timing need the first pass.
4. **Make the protected public read useful.** A recruiter should still see the problem, ownership, a safe decision, and an honest outcome before accessing protected media. Inspect this in a fresh locked session, not only an unlocked preview.
5. **Add behavior evidence before more screenshots.** One complete task, a meaningful changed state, or an authoring boundary usually proves more than another static screen.
