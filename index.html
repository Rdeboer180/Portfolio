01 / About Me

The craft keeps evolving. The process never settles.

I started in visual communications and followed the work into the browser, learning HTML and CSS because I wanted to understand what happened after a design left the canvas. At Tire Rack, that grew into design systems, AEM templates, and reusable components shaped in close partnership with engineering.

Today, I’m pushing that same curiosity further. I build my own products from the first idea through a self-governed system and into working software, creating custom tools and workflows along the way to remove repetition, protect the rules, and shorten the distance between an idea and something production-ready.

I’m still a designer at my core, and brand and design systems are still my specialty. My toolbelt has simply expanded around them.

I try not to let what I already know become the edge of what I can do. I’m constantly exploring new ways to bring AI into how I design, build, and maintain systems. That means improving internal tools and workflows at Tire Rack while building products like PlayDraft and LoopStack outside of it. Having something real to make, test, break, refine, and maintain is how I learn best.

I mapped where fourteen professional years and earlier practice actually landed, and what I am still leveling up, in The Forge.

03 / How I work

Good product work has to travel.

I don’t treat Figma, code, documentation, or a prompt as the finish line. They’re working surfaces for the same product decision. I move between them depending on what will answer the question fastest, and what I learn in one should be allowed to change the others.

Design systems make that movement easier, but they aren’t the whole job. The work is defining the problem, making tradeoffs visible, testing what becomes real, and leaving enough context for the next designer, engineer, or agent to make a good decision without me in the room.

See this in the work →Explore the live system →

Use the surfacethat answers fastest.

The file is not the finish line.

  1. Shared Product Context

    System knowledge

    Intent, decisions, and standards that can travel.

    Two-way with every surface on the board: Figma, the codebase, documentation, agent workflows, QA, the team, and governance.

  2. Figma / Canvas

    Design · Explore · Align

    Figma still starts and steers the conversation.

    Two-way with the Codebase and with the Shared Product Context.

  3. Code Connect·Button → <Button variant="primary">

  4. Codebase

    Implement · Maintain · Scale

    Turn system decisions into real products. Feed what production teaches back into the system.

    Two-way with Figma and with the Shared Product Context.

  5. Documentation

    Reference

    Write the system down so people who never open the Figma file or the code can still use it.

    Two-way with the Shared Product Context.

  6. Agent workflows

    Apply

    Carry system context into AI workflows, prototypes, and implementation requests.

    Two-way with the Shared Product Context.

  7. QA

    Validate

    Catch drift, accessibility issues, and system mismatches before they ship.

    Two-way with the Shared Product Context.

  8. Team

    Collaborate

    Help specialists share context, challenge decisions, and evolve the system together.

    Two-way with the Shared Product Context.

  9. Governance

    Guide

    Define guardrails, handle exceptions, and decide when patterns should change.

    Two-way with the Shared Product Context.

The loop

How the board gets used: four beats, and the fourth feeds the first.

  1. [ 01 ]

    Define the rules

    Starts at the Shared Product Context. Problem, people, constraints, and proof come before a tool picks the direction.

  2. [ 02 ]

    Explore across surfaces

    Figma / Canvas and the Codebase, in whichever order answers fastest. Either is allowed to change the system. The Figma MCP server hands an agent the mapped component and its tokens rather than a screenshot of the frame.

  3. [ 03 ]

    Learn from what becomes real

    QA and the Team report back: edge cases, accessibility gaps, and what production actually did with the rule.

  4. [ 04 ]

    Feed it back into the system

    Into Documentation, Agent workflows, and Governance: the guidance the next designer, engineer, or agent starts from.
