Eight Wrong First Drafts

Raw material for a post about product evolution. Eight times the first idea was the obvious one, and eight times something measurable said otherwise — with the numbers that said it. Most of these were caught before users saw them. Two were not.

The first idea is a hypothesis. The cost of testing it is almost always lower than the cost of shipping it.

Caught by simulation

Ideas that were coherent, popular, and provably backwards.

01

The scoring rule that rewarded exactly what it punished

First idea

Pay drafters for reaching — taking something later than the world takes it. Reward the gem-finder, so chalk never becomes the solved meta.

The data

400 simulated drafts per cell. It rewarded chalk 99–100% of the time — the precise inverse of its purpose. The obvious fix, normalising across the whole pack, just moved the win to the last seat instead (~90–100%). A seat lottery wearing a skill mechanic.

Shipped

Honest chalk scoring, and a comment saying so out loud. With a static popularity list and no outcome data, "did you find a gem" is not measurable — you cannot detect a gem without evidence that it was one.

02

Locking each round to one category

First idea

Randomise a category per round; only that category is draftable. Categories become maximally relevant, diversity is structural, no scoring change needed.

The data

Every board is half the pack. The smallest fast-food category is 14 items — about 7 on a live board, against one pick per seat. At six seats the last picker chooses from one card; at eight the category is exhausted before the round completes. And the inversion: it is safe in the deep packs where categories are already nearly free, and breaks in the shallow packs where they would actually matter.

Shipped

Nothing yet — narrowed to one locked round with a depth guard, plus a softer bonus variant. The reel animation that made the idea appealing was built anyway; it works for either mechanic.

Caught by measuring instead of reasoning

Where the confident diagnosis and the true one were different things.

03

The 650 MB build upload

First idea

Untracked media directories — screenshots, demo reels, design references — are bloating every build. Add them to the ignore file.

The data

Inspected the actual archive instead of guessing. The ignore file was excluding all of that correctly. 624 MB of the 650 MB was .git — the one rule in the file that does nothing, because the build tool re-adds the directory after applying the patterns.

Shipped

650 MB → 25 MB. Verified by diffing both archives file-by-file: identical apart from .git.

04

"Rewarding diversity" would have changed nothing

First idea

Give a bonus per distinct category on a roster, so players spread out instead of stacking.

The data

Pulled the top value in every category. In movies and music every major category tops out at 98–100. A five-pick roster spanning five categories costs about two points versus pure chalk. Players were already drafting diverse rosters by accident.

Shipped

Dropped. The lever was never variety — it was scarcity. Which pointed at a mechanic already built and shelved.

Caught by using it live

Two bugs that survived mockups, fixtures, and a full test suite, then died in minutes against a real board.

05

"kev is close behind · 0 picks"

First idea

A live race bar: name the leader, show the gap. Looked right in every mockup and every test fixture.

The data

On the first pick of a real draft it read "kev is close behind · 0 picks." True by subtraction — 50 minus 0 is inside the threshold — and nonsense as a sentence, shown at the one moment nobody is chasing anybody. A second bug in the same session: a green ↑ rendering inside a red border, because the mover's outline borrowed the bar's tone. Two signals describing different people.

Shipped

A chaser now has to actually be on the board; the mover's colour follows the direction of the move, not the reader's own standing.

06

The silent room

First idea

The client that just picked sends the "you're on the clock" push to the next player. Simple, no server work.

The data

It only works when a live client made the pick. The timeout sweeper has no client — so when a casual player missed their clock, the next player was never told they were on it. That cascades: A times out, B is never alerted, B times out. A room can auto-draft itself to completion in total silence. The competitive mode had already fixed exactly this and left a comment describing the bug word for word. Nobody noticed it applied to casual too.

Shipped

Casual announces its own turns from the database, same as competitive.

Caught by reading the code against its own comments

The most expensive category — where a comment or a constant asserted something the code did not do, and everyone believed the comment.

07

A centred layout that was never centred

First idea

Centre the achievement celebration as one composition, and pin the button to the bottom. Written, commented, and marked fixed — six days earlier, in response to the same complaint.

The data

The container said justify-content: center. Its last child said margin-top: auto. An auto margin consumes the free space before justify-content ever sees it — so the centring was a silent no-op, and the gap the comment was written to close simply reopened somewhere else. The comment described an intent the code contradicted, and nothing caught it.

Shipped

The composition got its own box, so there is real free space to centre inside. The note now records why the box exists, not just what it is meant to look like.

08

An alert that was wrong by 4×

First idea

Tell competitive players how long they have when their turn starts. The push said "2 minutes to pick."

The data

The competitive clock is 30 seconds. The two minutes almost certainly came from a nearby constant — clock plus sweeper lag — but that lag is what an abandoned pick costs everyone else, not time the player ever had. Surfaced only because someone specifying an unrelated feature said "since it's 30 sec clocks" and the number did not match.

Shipped

"30 seconds to pick." On the one mode whose own code comment calls the alert the product, a player told they had four times the time they actually had was being walked into a missed turn by the notification.

What it adds up to

  • A mechanic can be finished and still not be ready. One bonus system was built, verified, and proven to work — on its verification run it flipped 2nd and 3rd, which was exactly the intent. It was shelved anyway, because there was no way to explain the result to the player who lost. A surprise you cannot explain afterwards is indistinguishable from a bug.
  • Simulate before you ship, measure before you diagnose. Four of these eight were killed by a query or a simulation that took minutes. The confident explanation and the true one were different every time.
  • Fixtures agree with you. Real data does not. Two bugs survived mockups, tests and review, then died within minutes of a real board — because a fixture never has a drafter with zero picks, and never has someone losing.
  • Comments rot into lies. The two worst-aged defects were both places where prose asserted something the code did not do, and everyone downstream trusted the prose. Write down why, not just what — a why is checkable.
  • Not-yet is a real answer. "Reward the hidden gem" was not rejected, it was deferred to a specific unlock: it needs population data that is already being collected. Knowing the trigger is different from saying no.
