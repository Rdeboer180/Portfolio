    The state that matters most
    Error. It's where trust is lost, and it's the state a mockup almost never shows. The failure keeps every choice, moves focus to a message that says so, and offers the next step instead of a dead end.
    
    
    What I'd want to validate
    Whether reviewers actually open a contract. Who should write the checks: design in plain language, or engineering in tests. And how much this overlaps component tests and Storybook a team already has, because a second source of truth is worse than none.
    
    
    What this isn't
    Not a feature proposal, not a test framework, and not a claim about how any team works internally. It's a small question asked in working form: if behavior traveled with the design, would review get faster and calmer?
