What this unlocks

Test the feel and the process first, then hand the team something to define

  • The feel

    Timing, order and motion only exist in a running page. Here you can slow every transition to quarter speed, read each duration from the code, and switch to reduced motion.

    A comp shows the first and last frame. This shows the middle.

  • The process

    Every path a shopper can take, end to end: no vehicle, one size fits, pick your size, a staggered front and rear set, and a tire that isn't made for the car. You can even switch vehicles halfway through a transition.

    Problems show up while they're still cheap to change.

  • The definition

    The team starts from behavior they can react to, with numbered dev notes, acceptance checks and a timing table attached. Then they define the architecture, data and integrations.

    The questions come earlier, and they're better questions.

          The handoff

          What engineering gets with this prototype

          The prototype is the spec. Each numbered pin on the product page matches a note here, and the checks run against the same state engine the page uses.

          Dev notes

          1. 1

            Never preselect a size that doesn't fit

            When exactly one size fits, the page selects it and says so. When two or more fit, it selects nothing, asks which size is on the car, labels Standard and Optional, and shows where the door placard is. Sizes that don't fit fold out of the list and stay one tap away under All 24 sizes.

            Owned by: fitOptions(), autoOption() and view().sel
          2. 2

            Every price belongs to a size that fits

            With no vehicle, the page shows From $142.00 and asks for the vehicle. With several fitting sizes, it shows the range across those sizes only. A staggered set has one set price. A new price counts to its value in 240ms.

            Owned by: view().price
          3. 3

            Where to buy passes exactly what fits, or says why it can't

            The hand-off carries the vehicle, each size and its quantity: 4, or 2 front and 2 rear for a staggered set. When no size fits, Where to buy is off with the reason under it, and three lines that come in the vehicle's size are offered, closest first: same season, then closest price.

            Owned by: view().cta and alternatives(); in production, the dealer and retailer integrations
          4. 4

            The sidewall check uses the shopper's own evidence

            Width, profile, construction and rim, load index and speed rating are each read off the size and set beside the door placard value for that vehicle. The first three must match. Load index and speed rating must meet or exceed the placard. The check opens in place of the fit line, fills the size in one slot at a time beside the placard rows, then condenses back into the fit line. Meanwhile the tire zooms to the size printed under the brand name, lights each part as it's read, and zooms back out once the box has collapsed. See the check runs it again.

            Owned by: decode(), runDecode() and VEHICLES[].fits[].plac
          5. 5

            One transition at a time, from where things are

            A new vehicle cancels the running transition and starts from each element's current position and opacity, so nothing stacks or jumps. Durations are CSS custom properties, and Slow ×4 multiplies the same values. Reduced motion swaps movement for static tags. Each settled fit change is announced once, focus stays on the control the shopper used, and the fit lives in the URL.

            Owned by: motionPlan(), supersede(), run() and announcement()

          Acceptance checks · also agent eval cases

          Run against

            Parity check: does the branch match the prototype?

            • The same five fit states and their copy: no vehicle, one size fits, choose your size, staggered set, not made for your vehicle.
            • No preselected size when two or more fit, and a Standard or Optional label on every option.
            • Where to buy carries the vehicle, each size and its quantity, and is off with a visible reason when nothing fits.
            • The durations and easings in the timing table, read from tokens, with Slow ×4 built from the same tokens.
            • Reduced motion: no movement, and static Confirmed or Not made tags.
            • One aria-live message per settled fit change, with focus left where the shopper acted.
            • vehicle, size and rear in the URL.

            Engineering decides: the fitment data source, including how standard, optional and staggered sizes are flagged; the dealer and retailer integrations that would receive a front and rear pair; analytics events for fit changes and hand-offs; and real performance budgets on low-end phones. I'd ask the fitment team before treating my placard rules as right.

            What this is, and what I'd ask

            What it isn't

            It isn't Bridgestone's product page, and it uses no internal knowledge. The tire is the real Turanza EverDrive. Its name, 36 sizes, 80,000-mile limited warranty and the $201.99 price for 225/65R17 come from bridgestonetire.com on Oct 29, 2026. Everything else is illustrative: the 24 sizes shown, other prices, load and speed ratings, vehicles, fitments, placard values, and which other Bridgestone lines come in which sizes. The product photo is Bridgestone's; the size printed on it is replaced with the one you choose. Colors follow Bridgestone's site (#EE0000 actions, #F5F5F5 panels, 87% black text); the type is not theirs.

            What I'd ask the team that defines it

            1. How is fitment data sourced for staggered and optional sizes, and does the product page know which size is standard?
            2. When a size is handed to a dealer, does the dealer re-check it against the vehicle?
            3. Which retailers and dealer platforms accept a front and rear size in one hand-off today?
